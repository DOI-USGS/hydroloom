### Rule 3. A function raises only when it cannot form its documented output

Proposed: a data problem raises only when the function has no correct answer to return. When the problem itself can be part of the answer, the function returns the answer and does not raise. A function that checks for problems therefore lists them, and a function that transforms a network raises on them.

Rows settled:

- D3-166: accept. A repeated (`id`, `toid`) pair is something `check_hy_graph` can list in its result, so it lists it (Python from its first release, R in M6). Functions that transform the network have no correct output on a repeated pair, so they raise at ingest (D3-57).
- D3-167: accept. On a table with no `id`, "only the `[any]` functions are callable, with no conversion" is a correct capabilities answer, so `capabilities` returns it.
- D3-162: accept. On a table with no `id`, none of the values `representation` can return applies, since A-2's `"hy"` means an identifier is present. So it raises, which agrees with D3-29 and D3-130.

Disposition: Agreed, warning on messy data that doesn't block function or in functions designed to help find problems is correct.

### Rule 3b. Problem rows are named by `id`

Rows settled:

### Rule 4. Validate what a function reads, and never cut the network over a coding detail

Proposed: a value the function does not read passes through as it arrives. A coding the function reads is accepted when it has one physical reading, and raises when it has none or several. A coding detail never silently turns a flowline into a terminal (the D3-56 precedent).

Rows settled:

- D3-152: accept. A flag column holding a value other than 0, 1, or missing passes through.
- D3-174: accept. At a split coded 0 and 2, the 0 is read as the main path.
- D3-158: neither the current behavior nor the listed alternative. Today a lone downstream flowline coded 2 (its main path clipped away) leaves the flowline above it a terminal, which cuts the network. Under this rule `add_toids` connects to the one downstream flowline instead. This is a third option the row does not list; it needs a case.
- I2-3: an `Inf` in an identifier column has no reading as an identifier and raises.

Disposition: Agree in concept -- but these would normally be warnings that some might want to treat as errors, this should not be advertised as supported behavior even when it does work. In session, 2026-10-28: `Inf` in an identifier raises. Agents draft the warning text in `remedies.json` and the maintainer reviews it later. The R changes from rule 4, part 9, and decision 8 land before M5.
