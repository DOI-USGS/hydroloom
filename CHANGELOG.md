## 0.1.0 (2026-11-05)

### Added

- The package version comes from the `py-v*` release tag, and `hydroloom.__version__` reports it.
- `add_toids` builds `toid`, each flowline's downstream flowline, from `fromnode` and `tonode`, the identifiers of the points at each end of every flowline. By default it keeps only the main path where a flowline splits, which needs a `divergence` column (1 main path, 2 minor path), and raises `HydroloomError` when `divergence` is missing or a split has no main path or more than one. A flowline that reaches no other gets the empty string that marks an outlet. `return_dendritic=False` keeps every downstream connection and issues a `FutureWarning`, since `to_flownetwork` is to replace it. A network that already has `toid`, or lacks `fromnode`/`tonode`, raises `RepresentationError`.
- `align_names` renames the columns hydroloom knows by another name to its standard names and changes nothing else: identifiers keep their type and a missing `toid` stays missing. `hy_reverse` renames standard names back to those of one source, given as `source="nhdplus"`, `"nhdplushr"`, `"3dhp"`, or `"hydrofabric"`, in lowercase, so `id` becomes `comid`. With `source=None`, the default, `hy_reverse` gives each standard name the alias most recently registered for it with `register_names`, and leaves a name with no registered alias unchanged. `is_hy` reports whether a table is in the form `as_hy` returns: standard names, an `id` column with no missing values, and identifier columns as text. `name_definitions` returns a table of every standard name and its definition.
- `as_hy` renames the columns hydroloom knows by another name to its standard names (`COMID` becomes `id`, `ToCOMID` becomes `toid`), turns identifiers into text, and gives a missing `toid` the empty string that marks an outlet (a flowline that flows to nothing else in the table). `representation` reports which representation a table follows (the pattern of its columns), such as an id/toid list or a fromnode/tonode list; it reads the column names and the `id` values only. `make_index_ids` returns an `IndexIds` that gives each flowline's downstream or upstream flowlines as integer positions, for walking the network, and `mode="both"` returns the two as a pair. All three raise `RepresentationError` when no column becomes `id` and `HydroloomError` when an `id` value is missing.
- `capabilities` reports which hydroloom functions accept a network as it stands, in a table sorted by function name, with one row per hydroloom function that takes a table and with the columns `function`, `available`, and `via`. `available` is `True` where the network follows the representation the function needs (the pattern of columns `representation` reports) and holds the fixed columns the function requires; it tests the shape of the table, not its values, so a function marked available can still raise on the data. `via` gives the one conversion that makes an unavailable function available, such as `add_toids`, which builds `toid` for a node table (one that gives the nodes at the two ends of each flowline in `fromnode` and `tonode`). It is `""` where the function is available or no single conversion reaches it. A table with no `id` column, or an object that is not a table, has no representation, so only the functions that take any table are available. R's `hy_capabilities` takes `include_conversions` to mark the functions `via` reaches as available; `capabilities` has no such argument, since `via` gives the same answer.
- `hydroloom.errors` holds the exception and warning classes hydroloom raises. `HydroloomError` subclasses `ValueError`. It is raised for a problem in the input table that the caller can fix. `RepresentationError` subclasses `HydroloomError`. It is raised when a table lacks the representation (the pattern of its columns, such as an id/toid list) or the columns a function needs. Two cases raise built-in exceptions that `except HydroloomError` does not catch. A vocabulary problem, a column name that hydroloom's list of names cannot resolve, raises `KeyError`. An identifier column that mixes text and numbers raises `TypeError`. Warnings other than deprecations are `HydroloomWarning`, and each one points at the line in the caller's code that made the call.
- `is_dendritic` returns `False` when the table records a divergence and `True` otherwise. It reads two things the table records: a `divergence` value of 2, which marks the minor path leaving a divergence in NHDPlus coding, and, unless `validate_data=False`, an `id` that repeats beside a `toid` column, which is how a flowline with two downstream connections is listed. Column names are aligned to hydroloom names first, so an NHDPlus table with `COMID`, `ToCOMID`, and `Divergence` gives the same answer as one already renamed with `as_hy`. A table `as_hy` cannot read raises what `as_hy` raises, including `HydroloomError` on an (`id`, `toid`) pair listed twice. A node table whose divergences show only as a shared `fromnode`, with no `divergence` column, returns `True`.
- `navigate_network_dfs` walks a network depth first from each flowline in `starts` and returns, for each unique start in the order given, the flowlines it reaches as a list of paths, each a pandas `Index` of identifiers in visit order. `direction` is `"down"` (along `toid`), `"up"` (against it), or `"downmain"` or `"upmain"`, which follow only the main connections that `downmain` or `upmain` mark. Where the walk can go on to more than one flowline it takes the smallest identifier in byte order of the identifiers as text first, so `"10"` comes before `"9"` and any row order of the input gives the same result. A path ends at an outlet going down or a headwater going up (a flowline with no flowline below it or above it), or where the walk turns back to a flowline it has already visited. With `reset=False`, the default, a flowline returned for one start is left out of the results for later starts; `reset=True` walks each start on its own. `network` may be a network table or the `IndexIds` that `make_index_ids` returns, built with `mode="to"` for the downstream directions and `mode="from"` for the upstream ones. A node table, which gives the nodes at the two ends of each flowline in `fromnode` and `tonode`, is converted with `add_toids` first for `"down"` and `"up"`; for `"downmain"` and `"upmain"` it raises `RepresentationError`.
- `register_names` registers input column names as aliases of standard names for the rest of the session, so `align_names`, `as_hy`, and `hy_reverse` recognize them: `register_names({"FlowlineID": "id"})` makes a `FlowlineID` column `id`. Aliases are stored in lowercase, so `hy_reverse` gives back `flowlineid`. `replace=True` drops earlier registrations and keeps the aliases hydroloom ships. Used as `with register_names(mapping):`, the registration is undone when the block exits. A value that is not a standard name, or an alias that is a standard name other than its value, raises `KeyError` and registers nothing.
- `sort_network` returns the rows of a network ordered upstream to downstream, so every flowline comes after every flowline that drains to it. Outlets, and flowlines that drain to the same flowline, are taken in byte order of their identifiers as text, so `"10"` comes before `"9"` and any row order of the input gives the same output. `split=True` adds `terminal_id`, the `id` of the outlet each flowline drains to, and `outlets` limits the result to the networks above the flowlines given in `outlets`. `add_topo_sort` sorts the same way and adds `topo_sort`, numbered from the number of flowlines down to 1 at the last outlet; it replaces an input `topo_sort` column, such as NHDPlus `Hydroseq`, under the input's name. Both raise `HydroloomError` when the network holds a cycle, a set of flowlines that drain back into themselves, or when a value in `outlets` is not an `id`. `sort_network` also raises it when `split=True` and one flowline in `outlets` lies upstream of another. A node table, where each flowline names the nodes at its upstream and downstream ends in `fromnode` and `tonode` and carries `divergence`, is converted with `add_toids` first; a table with neither `toid` nor node columns raises `RepresentationError`.
