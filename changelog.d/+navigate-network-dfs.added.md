`navigate_network_dfs` walks a network depth first from each flowline in `starts` and returns, for each unique start in the order given, the flowlines it reaches as a list of paths, each a pandas `Index` of identifiers in visit order. `direction` is `"down"` (along `toid`), `"up"` (against it), or `"downmain"` or `"upmain"`, which follow only the main connections that `downmain` or `upmain` mark. Where the walk can go on to more than one flowline it takes the smallest identifier in byte order of the identifiers as text first, so `"10"` comes before `"9"` and any row order of the input gives the same result. A path ends at an outlet going down or a headwater going up, or where the walk turns back to a flowline it has already visited. With `reset=False`, the default, a flowline returned for one start is left out of the results for later starts; `reset=True` walks each start on its own. `network` may be a network table or the `IndexIds` that `make_index_ids` returns, built with `mode="to"` for the downstream directions and `mode="from"` for the upstream ones. A node table, where each flowline names the nodes at its two ends in `fromnode` and `tonode`, is converted with `add_toids` first for `"down"` and `"up"`; for `"downmain"` and `"upmain"` it raises `RepresentationError`. A start that is not an `id`, a network with a cycle, an index built in the wrong mode, and a main direction on a network with no main-path flags raise `HydroloomError`; a `direction` outside the four raises `ValueError`.
