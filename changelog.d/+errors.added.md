`hydroloom.errors` holds the exception and warning classes hydroloom raises. `HydroloomError` subclasses `ValueError`. It is raised for a problem in the input table that the caller can fix. `RepresentationError` subclasses `HydroloomError`. It is raised when a table lacks the representation (the pattern of its columns, such as an id/toid list) or the columns a function needs. Two cases raise built-in exceptions that `except HydroloomError` does not catch. A vocabulary problem, a column name that hydroloom's list of names cannot resolve, raises `KeyError`. An identifier column that mixes text and numbers raises `TypeError`. Warnings other than deprecations are `HydroloomWarning`, and each one points at the line in the caller's code that made the call.
