`capabilities` reports which hydroloom functions accept a network as it stands, in a table with one row per hydroloom function, sorted by function name, and the columns `function`, `available`, and `via`. `available` is `True` where the network follows the representation the function needs (the pattern of columns `representation` reports) and holds the columns it reads; it tests the shape of the table, not its values, so a function marked available can still raise on the data. `via` is `""` where the function is available and, for a function reachable after one conversion, gives the one conversion, such as `add_toids` for a node table, which gives the nodes at the two ends of each flowline in `fromnode` and `tonode`. A table with no `id` column, or an object that is not a table, has no representation, so only the functions that take any table are available. R's `hy_capabilities` takes `include_conversions` to mark the functions `via` reaches as available; `capabilities` has no such argument, since `via` gives the same answer.
